# 書籍サンプルプログラムを大改造

このプロジェクトは、書籍に掲載されたサンプルプログラムをベースに、構造全体を抜本的に再設計したものです。
従来の手続き型の構成を見直し、現代的な設計思想を導入して再構築しています。

## 1. はじめに

このプロジェクトは、書籍で学んだ学習者が、より保守性の高い構造と、明確な責任分担をもった設計思想を学ぶための教材です。

## 2. 使用技術

- 言語：Python、Pyxel  
- 設計技術：
  - オブジェクトのコンポーネント化
  - 処理のMVC化
  - データ構造の独立化

## 3. 想定ユーザー・利用シーン

- 書籍の学習者を対象としています。
- より高度な構造設計を学ぶための教材として最適です。
- 現場での開発にも通用する構造的な考え方の習得が目的です。

## 4. インストールと実行

このプロジェクトには Python と最新の Pyxel が必要です。

```bash
# リポジトリをクローン
git clone https://github.com/kureha001/Learn_Pyxel.git
cd Learn_Pyxel

# 必要なライブラリをインストール
pip install -r requirements.txt

# プログラムを実行
python main.py
```

## 5. 特徴

書籍サンプルのシンプルな構造から脱却し、実用的な保守・拡張が可能なアーキテクチャへと再設計されています。
Python初学者向が理解を深めるために、関数名・変数名など随所に日本語を多用しています。
その為、コーディングスタイルなどはPEP8に準拠していません。
以下に、設計上の主要な特徴を示します。

### 5.1 コンポーネントの分離と構造化

- `main/更新コントローラ` や `main/描画コントローラ` のように、処理の種別ごとに明確にディレクトリが分離されており、各機能が独立したモジュールとして定義されています。
- 処理単位（出現、移動、発射、衝突など）ごとにサブパッケージを設け、責務を限定することで、保守性と理解性が向上しています。


### 5.2 MVC風の構成

- **Controller（コントローラ）**：
  - `更新コントローラ` や `描画コントローラ` が、全体の流れを制御する中心的な役割を担います。
  - コントローラはプロセス（移動・衝突・発射・出現・描画）で細分化され、必要なエンティティクラスのアクションメソッドを実行します。
- **Model（データとロジック）**：
  - `キャラクタ/自機/FN描画.py` 等が処理のロジックを担当。
  - 内部に`仕様クラス`と `情報クラス`を持ち、静的・動的データが分離されています。
- **View（描画）**：
  - 各キャラクタに描画専用の関数が設けられており、表示処理の分離が徹底されています。

### 5.3 データとロジックの分離

- 各キャラクタ（例：`キャラクタ/自機/`）において、描画・移動・衝突・発射などの処理は別々の関数（FN○○）にモジュール分割されており、データとの分離がなされています。
- 固定仕様は `DB.py` に集約され、ゲーム進行やオブジェクトの性質により変化する状態は、エンティティの仕様・情報クラスに保持されます。

### 5.4 拡張性・保守性の配慮

- ディレクトリ構成と命名規則が整理されており、新たなキャラクタや処理を追加する際も最小限の変更で済む構造です。
- 各サブシステムが疎結合であるため、処理の入れ替えや再利用が容易です。

---

本設計により、サンプルコードの「理解するためのコード」から、「成長できるコード」へと進化しています。
